# trim-mmio：可控制的 MMIO 测试寄存器

`trim-mmio` 在指定的客户机物理地址创建一个可读写寄存器，为通过
`/dev/mem` 访问硬件的客户机程序提供可控制的测试输入。
每个实例的地址、长度、默认值和恢复定时器相互独立，可以重复使用
`-device` 创建多个寄存器。

## 创建实例

```text
-device trim-mmio,id=mmio0,addr=0xFD6D0960,size=2,default=0x102
```

| 参数 | 含义 |
| --- | --- |
| `id` | 必填，实例名称，供 QMP/HMP 控制；多个实例必须使用不同名称。 |
| `addr` | 必填，寄存器的实际客户机物理地址，支持 64 位地址；须按 `size` 对齐。 |
| `size` | 可选，寄存器长度，单位为字节，支持 `1`、`2`、`4`，默认 `4`。 |
| `default` | 可选，启动、机器重置及定时恢复时的原始值，默认 `0`；不得超过 `size` 的位宽。 |

地址完全由 `addr` 指定，设备不内置机型地址或自动追加偏移。
创建时会拒绝与已有有效内存映射重叠的范围。应选择客户机中持续空闲的
物理地址：设备不会修改 ACPI、设备树或固件资源表，也不能阻止客户机以后
把其他设备的 PCI BAR 配置到同一地址。设备仅支持启动时创建。

## 从寄存器描述填写参数

当目标平台提供寄存器描述时，找到要模拟的 MMIO 条目，并将其中的实际
寄存器地址和访问宽度填入设备属性。例如一个位于 `0xFD6D0960` 的 16 位
输入寄存器可以配置为：

```text
-device trim-mmio,id=input0,addr=0xFD6D0960,size=2,default=0x102
```

字段对应关系如下：

| 寄存器描述 | trim-mmio 的配置方法 |
| --- | --- |
| 实际寄存器地址 | 直接填入 `addr`。 |
| 访问宽度 | 直接填入 `size`。 |
| 逻辑名称 | 用来选择容易识别的 `id`，不是 MMIO 地址。 |
| 位定义和读写处理 | 据此推导原始寄存器值；设备不自动进行位提取或逻辑取反。 |
| 页映射基址和长度 | 仅用于客户机建立映射，不是单个寄存器的地址和长度。 |
| 权限和逻辑范围 | 属于客户机程序约束，不直接作为设备属性。 |

如果客户机先映射 `0xFD6D0000` 所在的 4 KiB 页，再访问页内偏移
`0x960`，设备仍应配置实际地址 `0xFD6D0960`。无需为整个 4 KiB 页创建
同值窗口。不同平台应使用各自寄存器描述中的实际地址。

同一物理寄存器只创建一个实例。不同逻辑功能可能指向相同地址，例如
多个状态指示功能共用 `0xFD6E0760`；这些别名应共享同一个实例。不要把
不同平台的寄存器描述合并成一套配置。

### 按键默认值与控制值

如果客户机在初始化时清除 bit9/bit10、置位 bit8，并每秒检查 bit1，
则 bit1 为 1 表示释放，为 0 表示按下。因此可采用以下测试值，同时保留
初始化使用的 bit8：

| 状态 | 原始值 | 说明 |
| --- | --- | --- |
| 释放 | `0x102` | bit8=1、bit1=1，适合作为 `default`。 |
| 按下 | `0x100` | bit8=1、bit1=0。 |

这些值根据上述位定义推导，用作测试初值，不是实机寄存器复位值转储。
不能把命令中的 `0`、`1` 普遍解释成松开和按下；例如这个按键的原始值
`0x0` 与 `0x1` 都使 bit1 为 0。

下面的命令展示创建寄存器和 HMP 控制台的方式；运行客户机程序时还需
搭配自己的启动参数：

```sh
qemu-system-x86_64 \
  -machine q35 -m 512 -display none -monitor stdio \
  -device trim-mmio,id=reset0,addr=0xFD6D0960,size=2,default=0x102
```

### 多个实例

例如一个平台包含一个输入寄存器和两个状态指示寄存器，可分别创建：

```text
-device trim-mmio,id=reset0,addr=0xFD6E0750,size=2,default=0x2
-device trim-mmio,id=status0,addr=0xFD6D0740,size=1,default=0x0
-device trim-mmio,id=status1,addr=0xFD6D0730,size=1,default=0x0
```

地址与长度应来自目标平台的寄存器描述。这里的状态寄存器以原始值 0
初始化，客户机可通过 bit0 读改写；设备不显示实际指示灯。选择这些配置
前，应确认客户机使用了对应平台的寄存器定义。

### 紧邻的寄存器

每个实例只占用 `addr` 到 `addr + size - 1`，不会扩展为整页。
因此，两个寄存器可以位于同一个 4 KiB 页内，甚至紧挨着，只要地址范围
不重叠且分别满足对齐要求。

下面仅演示两个紧邻的 16 位寄存器布局，不代表某个实机的寄存器表：

```text
-device trim-mmio,id=mmio0,addr=0xFD6D0960,size=2,default=0x1111
-device trim-mmio,id=mmio1,addr=0xFD6D0962,size=2,default=0x2222
```

| 实例 | 占用地址 | 默认值 |
| --- | --- | --- |
| `mmio0` | `0xFD6D0960` 至 `0xFD6D0961` | `0x1111` |
| `mmio1` | `0xFD6D0962` 至 `0xFD6D0963` | `0x2222` |

通过 HMP 临时修改第一个寄存器，并分别读取两个寄存器：

```text
trim-mmio mmio0 0x1234 5
xp /1hx 0xFD6D0960
xp /1hx 0xFD6D0962
```

计时到期前，读取结果分别为 `0x1234` 和 `0x2222`；经过 5 秒虚拟时间后，
第一个恢复 `0x1111`，第二个仍为 `0x2222`。客户机应分别使用 16 位访问，
不要把这两个实例合并为一次跨边界的 32 位寄存器访问。

紧邻布局必须显式填写正确的 `size`。如果第一个实例省略 `size`，默认的
4 字节会覆盖 `0xFD6D0960` 至 `0xFD6D0963`，与第二个实例重叠，QEMU 将
拒绝启动并报告 `overlaps region`。相邻的 8 位寄存器则使用 `size=1`，
地址可相差 1；`size=2` 和 `size=4` 的地址分别要求 2 和 4 字节对齐。
同一地址的不同位若属于同一个物理寄存器，应共用一个实例。

## HMP 控制

```text
trim-mmio id value [duration]
```

直接设置值，并取消该实例以前安排的恢复：

```text
trim-mmio reset0 0x100
```

设置为按下状态，5 秒虚拟时间后恢复该实例的 `default`：

```text
trim-mmio reset0 0x100 5
```

立即恢复释放状态，并取消旧计时：

```text
trim-mmio reset0 0x102
```

可以用已有的 HMP 物理内存查看命令读取当前寄存器：

```text
xp /1hx 0xFD6D0960
```

`value` 和 `duration` 接受完整整数，支持十进制和 `0x` 前缀的十六进制，
不接受算术表达式。`duration` 为正整数秒，最多 `4294967295`，但截止时间
仍必须能用 QEMU 的虚拟时间表示。省略它表示不安排恢复；传入 `0` 会报错。

## QMP 控制

启动时添加 QMP 连接，例如：

```text
-qmp unix:/tmp/trim-mmio.qmp,server=on,wait=off
```

客户端连接后先读取 QMP greeting，再启用命令：

```json
{"execute":"qmp_capabilities"}
```

直接设置：

```json
{"execute":"trim-mmio","arguments":{"id":"reset0","value":256}}
```

设置后在 5 秒虚拟时间后恢复：

```json
{"execute":"trim-mmio","arguments":{"id":"reset0","value":256,"duration":5}}
```

成功时返回：

```json
{"return":{}}
```

JSON 数值使用十进制，`256` 对应 `0x100`，`258` 对应 `0x102`。
`value` 的范围为 0 到 `2^(8*size)-1`。未知 ID、其他设备类型、超出
位宽的值和无效时长都会报错，不改变原值或已有恢复计时。

## 读写和生命周期

寄存器按小端解释，支持映射范围内的 1、2、4 字节访问及非对齐访问。
写入一部分字节会保留其他字节，因此客户机的读—改—写流程可以正常回读。
客户机写入和监控命令修改的是同一份值，以最后一次写入为准；监控命令
不会锁住寄存器。客户机写入不取消已安排的定时恢复，到期仍恢复整个
`default` 值。

每个实例最多保留一个恢复定时器。新的有效控制命令替换旧计时；省略
`duration` 则取消旧计时。计时使用 `QEMU_CLOCK_VIRTUAL`，虚拟机暂停时
停止推进，恢复运行后继续。若以 `-S` 启动，应先执行 `cont` 才会自然计时。
客户机程序可能按周期轮询输入，观察到的持续秒数可能受轮询相位影响，
不保证恰好等于命令的 `duration`。

机器重置会取消计时并恢复默认值。迁移或保存状态包含当前值和恢复截止
时间；目的端必须配置相同的设备 ID、地址、长度与默认值。多实例通过
设备 ID 对应，不依赖命令行中的创建顺序。

## 模拟范围

这是通用 MMIO 寄存器测试设备，不包含 GPIO 中断、引脚复用、方向控制
或芯片特有的写一清零语义，不会产生蜂鸣器声音，也不会自动识别机型。
客户机程序使用的其他 I/O port、Super I/O、sysfs 等接口仍需相应环境。
客户机还必须允许程序访问 `/dev/mem`，并使用正确的平台配置；仅创建这个
设备不代表所有程序或系统服务均可运行。
