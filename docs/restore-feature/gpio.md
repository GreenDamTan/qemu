# 独立 GPIO MMIO 设备

`-device gpio` 提供一个可从监视器注入原始位值的 MMIO 寄存器，每个实例对应一个寄存器。
它独立于其他 MMIO 辅助功能，不依赖其他设备，也不是 Linux GPIO 控制器或设备间引脚连线接口。

## 1. 启动配置

接口格式如下；尖括号和 `1|2|4` 是占位说明，不应原样交给 shell：

```text
-device gpio,id=gpio0,addr=<64位实际物理地址>,size=1|2|4,gpio-mask=<可注入位掩码>,write-mask=<guest可写位掩码>,default=<原始初值>
```

| 属性 | 默认值 | 含义 |
| --- | --- | --- |
| `id` | 无，必填 | 实例的唯一标识，供命令定位和迁移配对使用 |
| `addr` | 无，必填 | 64 位实际物理地址，按 guest 物理地址空间解释 |
| `size` | `4` | 寄存器长度，单位字节，只能是 `1`、`2`、`4` |
| `gpio-mask` | `0xffffffff` | 监视器可注入的位；此特殊值自动适配 `size` 位宽 |
| `write-mask` | `0` | guest 可写位掩码，默认 guest 写不改变值 |
| `default` | `0` | 完整寄存器的原始初值，也是 reset 恢复值 |

`addr` 不是寄存器块内偏移、guest 虚拟地址或宿主指针，不会自动分配。
配置须满足以下约束：

- `id` 必须唯一；`addr` 必须自然对齐，即 `addr % size == 0`。
- 恰好映射 `size` 字节，范围为 `[addr, addr + size)`，不会自动扩展成整页窗口。
- 创建时若与已有地址映射冲突，则拒绝创建；设备仅在启动时配置，不支持热插拔。
- 省略或显式设置 `gpio-mask=0xffffffff`，均表示自动覆盖 `size` 对应的全部位。
- 因此这个特殊值对 `size=1`、`size=2` 也合法，分别得到 `0xff`、`0xffff`。
- 除上述特殊值外，显式 `gpio-mask`、`write-mask`、`default` 必须能装入 `size`。
- `gpio-mask` 不得为零；`write-mask` 必须是 `gpio-mask` 的子集，可以为零。

`size=1/2/4` 的无符号值上限分别是 `0xff`、`0xffff`、`0xffffffff`。
`default` 不必是 `gpio-mask` 的子集，可以包含其他位的固定初值。
特殊值规则仅适用于 `gpio-mask`，不适用于 `write-mask`、`default` 或命令 `value`。

## 2. 多实例与相邻寄存器

以下是可追加到系统模拟器启动命令的参数片段：

```sh
-device gpio,id=gpio0,addr=0xFD6D0960,size=2,gpio-mask=0x2,write-mask=0,default=0x2 \
-device gpio,id=gpio1,addr=0xFD6D0962,size=2,gpio-mask=0x1,write-mask=0x1,default=0
```

这两个地址**仅用于格式示例**，使用前必须确认所选机器对应地址空闲。
示例初值也只是配置选择，不代表实际硬件的 reset 值。

| 实例 | 映射的字节地址 | 用途 |
| --- | --- | --- |
| `gpio0` | `0xFD6D0960` 至 `0xFD6D0961` | bit1 输入，guest 不可写 |
| `gpio1` | `0xFD6D0962` 至 `0xFD6D0963` | bit0 可读写 |

两个 16 位寄存器紧挨但不重叠，各自拥有独立的当前值和定时器。
若省略 `size`，默认 4 字节会使第一个寄存器覆盖到 `0xFD6D0963`，与第二个范围重叠。
而且 `0xFD6D0962` 本身不满足 4 字节自然对齐，不能用默认 `size=4` 表达这组寄存器。

同一个物理寄存器的不同名称或位字段别名应共用一个实例、同一个 `id`，不要重复映射同地址。
需要控制多个位时合并 `gpio-mask`；一次命令更新其中所有选定位，须在 `value` 中一并表达它们。
不同物理寄存器则使用不同实例，命令只影响指定 `id`。

## 3. 原始位值与掩码

命令 `value` 和配置 `default` 都是**原始物理位模式**，不是把选定位右移后的逻辑值。
设备没有 `active-low` 属性；低有效含义由调用者通过写 `0` 或相应 bit 掩码表达。
命令的完整 `value` 必须先能装入 `size`，不能依靠掩码忽略超宽部分来使输入合法。

令 `M` 为实际 `gpio-mask`，命令更新规则为以下按寄存器位宽进行的运算：

```text
新值 = (当前值 & ~M) | (value & M)
```

- `M` 选中的位全部取自 `value`，没有置位的选定位会被清零。
- `M` 未选中的位保持当前值，`value` 在这些位置上的位不会写入寄存器。
- 对 bit1，置高必须传 `0x2`，置低传 `0`，而不是用逻辑值 `1` 表示高。
- **`gpio gpio0 0x1` 不会置位 bit1！** 在上述配置中它会清零 bit1，且不会改变 bit0。

例如另一个配置若为 `size=2,gpio-mask=0x2,default=0xA502`，注入 `0` 后是 `0xA500`。
这说明非选定位受保护；该数值只是位操作示例，不是硬件初值声明。

## 4. HMP：输入 bit1 与读取核对

命令格式：

```text
gpio <id> <value> [duration]
```

`value`、`duration` 必须是严格的无符号整数字面量；HMP 可用十进制或 `0x` 前缀十六进制。
不接受负数、浮点数、表达式、单位后缀或尾随字符；`duration` 如提供，必须大于零。

沿用 `gpio0` 的 `gpio-mask=0x2,default=0x2,write-mask=0`，按低有效输入解释：

```text
(qemu) xp /1hx 0xFD6D0960
(qemu) gpio gpio0 0
(qemu) xp /1hx 0xFD6D0960
(qemu) gpio gpio0 0x2
(qemu) xp /1hx 0xFD6D0960
```

在小端目标上，三次读取的数据依次应为 `0x0002`、`0x0000`、`0x0002`。
注入 `0` 模拟 bit1 低电平，注入 `0x2` 恢复高电平；guest 写无法改变这个输入。

现有 HMP 的 `xp /1hx` 格式有效：`1` 表示一项，`h` 表示 16 位，`x` 表示十六进制。
也可写成 `/1xh`；`xp` 检查物理内存，不是虚拟地址，也不是专用 GPIO 查询命令。
对于 `size=1`、`size=4`，分别选用 `/1bx`、`/1wx`，不要无意读出实例范围。

临时拉低 5 个虚拟秒：

```text
(qemu) gpio gpio0 0 5
```

到期后 bit1 恢复为 `default` 中的 `0x2`；计时期间再次执行命令的行为见定时器规则。

## 5. QMP：先握手再注入

连接已配置的 QMP 通道后，先接收欢迎消息，再发送能力协商：

```json
{"execute":"qmp_capabilities"}
```

收到成功响应后，才发送 GPIO 命令：

```json
{"execute":"gpio","arguments":{"id":"gpio0","value":0,"duration":5}}
```

省略 `duration` 的命令示例：

```json
{"execute":"gpio","arguments":{"id":"gpio0","value":2}}
```

这里的 JSON 数值必须使用十进制整数：bit1 高电平写 `2`，不能写 `0x2` 或字符串 `"0x2"`。
也不要使用小数、指数形式或负数；`duration=0` 非法，持续保持应省略 `duration`。
QMP 与 HMP 共享相同的位宽检查、掩码更新和定时器语义。

## 6. guest 访问与 bit0 可读写示例

寄存器按**小端**布局，支持 guest 的 1、2、4 字节 MMIO 访问。
一次访问应完整落在该实例范围内：1 字节实例用字节访问，2 字节实例用字节或半字访问。
4 字节实例可以使用字节、半字或 32 位访问；不要依赖跨实例访问的效果。
偏移 `0` 对应低 8 位，偏移 `1` 对应 bits 8–15，后续字节依此类推。

读取返回当前原始值的相应部分；部分写只可能更新本次访问覆盖且被 `write-mask` 选中的位。
其他字节、不可写位以及 `gpio-mask` 之外的位均保持当前值，不因全字写而被清零。
`write-mask=0` 时 guest 写不改变任何位；guest 写也不修改 `default`，不取消定时器。

沿用 `gpio1` 的 `gpio-mask=0x1,write-mask=0x1,default=0`，按表中顺序操作：

| guest 操作 | 随后读取完整 16 位值 | 说明 |
| --- | --- | --- |
| 初始读取 `0xFD6D0962` | `0x0000` | 来自配置初值 |
| 向 `0xFD6D0962` 写 16 位 `0x0001` | `0x0001` | bit0 置位 |
| 向 `0xFD6D0963` 写 8 位 `0xff` | `0x0001` | 高字节不可写，低字节未覆盖 |
| 向 `0xFD6D0962` 写 16 位 `0xffff` | `0x0001` | 只有 bit0 可写，其他位受保护 |
| 向 `0xFD6D0962` 写 8 位 `0x00` | `0x0000` | 部分写清零 bit0 |

可在现有 HMP 中用 `xp /1hx 0xFD6D0962` 核对各步结果。
监视器也可用 `gpio gpio1 0x1`、`gpio gpio1 0` 控制 bit0；注入权限由 `gpio-mask` 决定。

## 7. 定时器与 reset

每个实例只有一个定时器，使用 **QEMU 虚拟时钟**，按 guest 运行时间推进，而非墙上时钟。
VM 暂停时不会消耗这里的持续时间，不能用宿主等待 5 秒来保证命令已经到期。

| 事件 | 当前值与定时器行为 |
| --- | --- |
| 创建实例 | 完整值初始化为 `default`，没有挂起的定时恢复 |
| 命令带 `duration` | 立即按 `gpio-mask` 更新，从本次命令起计正整数秒，替换旧定时器 |
| 命令省略 `duration` | 立即按 `gpio-mask` 更新，并取消旧定时器 |
| 定时器到期 | 仅把 `gpio-mask` 选定位恢复到 `default` 的对应位，其他位保持当前值 |
| guest 写 | 按 `write-mask` 更新，原有定时器继续运行 |
| reset | 恢复完整 `default`，并取消该实例定时器 |

定时器不会叠加，也不会保存多层历史值；恢复目标是 `default`，不是注入前的值。
即使 guest 在计时期间改写了可写位，到期仍会恢复 `gpio-mask` 中的全部选定位。
定时恢复与 reset 不同：前者只恢复掩码内位，后者恢复整个寄存器。

## 8. 迁移要求

- 源端和目的端按实例 `id` 配对，不依靠相同地址或创建顺序代替 ID。
- 目的端应预先配置对应实例，并保持 `addr`、`size`、`gpio-mask`、`write-mask`、`default` 一致。
- 迁移状态包括完整当前 `value` 和定时器状态，不能只在目的端重新加载初值。
- 挂起的恢复随虚拟时钟状态继续，而不是在目的端重新开始一个完整的 `duration`。

## 9. 使用边界与排查

- 只提供 MMIO 映射，不自动提供 `/dev/gpiochip*` 或 `gpio-keys`。
- 不包含固件资源描述或 guest 驱动；guest 必须已有或自行实现相应访问方式。
- 不模拟完整 pinmux、方向控制、IRQ 或厂商 GPIO 芯片，也不承诺与现有工程完整兼容。
- 创建时的冲突检查不能保证后续 PCI BAR 重映射不重叠；必须选择空闲且不会被后续占用的地址。
- 配置失败时先检查必填项、ID、对齐、范围冲突，以及掩码和初值是否满足位宽与子集约束。
- 读值不符时检查是否误用了右移后的逻辑值、错误字节偏移、访问宽度或监视器目标端序。
- 定时恢复未发生时检查 VM 是否运行，以及旧定时器是否已被后续命令替换、取消或被 reset 清除。
